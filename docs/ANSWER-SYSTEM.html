Answer system: TRUE, FALSE, or UNKNOWN, each with a certificate ​

Purpose ​

Answer a question with one of three values, and attach to every TRUE or FALSE a certificate that a reader can check without trusting the system:

  • TRUE: a certificate that the statement holds.
  • FALSE: a certificate that it does not (a counterexample, or a refutation).
  • UNKNOWN: no certificate was found. The answer names the blocking step.

This is the intended meaning of the system. It does not claim that every question has a computable answer. Undecidable questions exist (the halting problem), and open problems such as the Clay problems have no certificate in this repository, so they answer UNKNOWN.

Answer rules (no exceptions) ​

  1. TRUE requires a certificate of type C1 or C2 (below). Nothing else produces TRUE.
  2. FALSE requires a counterexample certificate: a witness that the statement fails, checked by the same kernel.
  3. A probable result is never TRUE or FALSE. It is UNKNOWN, with the probability named.
  4. A cited source is evidence, not a certificate. A sourced answer is reported as SOURCED, never as TRUE.
  5. A question that cannot be formalised is UNKNOWN, with the reason "not formalised".
  6. A refusal of any step is UNKNOWN with that step named.

Certificate types ​

TypeWhat it isChecked byYields
C1A Lean proof of the statement, no sorry, no axioms beyond the kernel'slean_ask (compile, #print axioms, sorry check)TRUE
C2An arithmetic witness: a factor with an exact product check, or a Miller–Rabin base proving compositenesstask_route (exact integer arithmetic)TRUE or FALSE
C3A cited source: a DOI that resolves to the canonical record, or an arXiv identifier whose abstract page resolves to the stated titleanswer-verify-doi (DOI); answer-verify-arxiv (arXiv, through web_fetch)SOURCED
C4A probable-prime result, or a text questionnoneUNKNOWN

C2 applies only where the check is exact: a found factor passes p × q = n, and a composite is proved by a base whose failure is an exact congruence. A probable prime is C4, not C2.

Routing ​

  1. Integer (decimal or hexadecimal): task_route. Composite or small prime → C2. Probable prime → UNKNOWN.
  2. Lean statement (a theorem with := by decide or a tactic proof): lean_ask. Conjunctions are split by lean_split, and the whole holds only if every part does (C1 per part).
  3. Text question: formalise it as a Lean statement first. If it cannot be formalised, UNKNOWN.
  4. Claim about a publication: doi-precedence-test. Resolves to SOURCED, never TRUE.
  5. Clay problems: UNKNOWN, with the reason that the statement is open. The Clay conditions are checked by clay-conditions-test and reported as NOT MET until the evidence exists.

Output shape ​

Every answer is JSON with these fields: question, value (TRUE, FALSE, SOURCED, or UNKNOWN), certificate (type, and the artefact a reader can check: a Lean file, a witness, or a DOI), reason, and checkedBy (the tool and the date). An UNKNOWN answer has blockingStep instead of certificate.

Todo list ​

Each item is done only when its acceptance test passes. An item that is not done stays [ ].

Current state (checked, not assumed) ​

  • T3 and T4 exist as tools (lean_ask, task_route), but no answer tool joins them yet.
  • T5 exists as a test (doi-precedence-test), and its current run shows 1 of 4 DOIs resolving to the canonical record.
  • T6 to T8 do not exist.

Limits ​

  • The system can only certify what it can formalise. Most open questions cannot be formalised in this repository.
  • A certificate is checked by this repository's tools. A reader who wants independence should re-run the checks with their own toolchain.
