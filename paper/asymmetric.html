src/iso/iec-18033-cryptography/asymmetric.lean · namespace Asymmetric · 11 theorems · wing the address

WHAT THIS FILE IS FOR. Everything cryptographic in this deposit before now was SYMMETRIC — FNV, SHA-256, HMAC, ChaCha20-Poly1305 — and a symmetric tag proves possession of a shared secret. It cannot say WHO produced something, because both parties can produce it. That is a boundary the deposit kept in prose.

Two facts are decidable, and they are the two that keep the container honest:

1 · A CHECKSUM IS NOT AUTHENTICATION. The container's first group holds 32 bits computed by a public function of the payload, so anyone who edits the payload recomputes it. Deciding this needs no cryptography at all — it is a counting statement about what a public function can distinguish.

2 · THE SIGNATURE DOES NOT FIT. An Ed25519 public key is 32 bytes and a signature is 64. A uuid is 16 bytes in total, of which 6 BITS are already spoken for. So a signature is carried beside the identifier, never inside it, and "the signature is in the uuid" is arithmetic, not policy.

No axioms, no Mathlib, no sorry.

Definitions

uuidBytes := 16
publicKeyBytes := 32
signatureBytes := 64
checkBits := 32
payloadBits := 42 + 48
widths := List.range (8 * uuidBytes + 1)
p := 2 ^ 255 - 19
L := 2 ^ 252 + 27742317777372353535851937790883648493

Theorem 34 (a_signature_is_four_uuids_and_a_key_is_two)sealed.

∀n∈widths,n≤uuidBytes⋅containersOf(n)∧n=0∨uuidBytes⋅containersOf(n)<n+uuidBytes∧containersOf(signatureBytes)=4∧containersOf(publicKeyBytes)=2∧signatureBytes=4⋅uuidBytes∧publicKeyBytes=2⋅uuidBytes
widths.all (fun n => (n ≤ uuidBytes * containersOf n) && (n == 0 || uuidBytes * containersOf n < n + uuidBytes)) ∧ containersOf signatureBytes = 4 ∧ containersOf publicKeyBytes = 2 ∧ signatureBytes = 4 * uuidBytes ∧ publicKeyBytes = 2 * uuidBytes
LaTeX source
\forall n \in \mathrm{widths},\; n \le \mathrm{uuidBytes} \cdot \mathrm{containersOf}\mathopen{}\left(n\right) \land n = 0 \lor \mathrm{uuidBytes} \cdot \mathrm{containersOf}\mathopen{}\left(n\right) < n + \mathrm{uuidBytes} \land \mathrm{containersOf}\mathopen{}\left(\mathrm{signatureBytes}\right) = 4 \land \mathrm{containersOf}\mathopen{}\left(\mathrm{publicKeyBytes}\right) = 2 \land \mathrm{signatureBytes} = 4 \cdot \mathrm{uuidBytes} \land \mathrm{publicKeyBytes} = 2 \cdot \mathrm{uuidBytes}

CARRYING IS CEILING DIVISION, AT EVERY WIDTH: the containers hold at least what was given them, and they never waste a whole container doing it. Four and two are what that law answers for a signature and a key.

Proof. by decide — by evaluation; no domain is walked. □

Theorem 35 (neither_the_key_nor_the_signature_fits_in_a_uuid)sealed.

∀n∈widths,containersOf(n)≤1=n≤uuidBytes∧containersOf(publicKeyBytes)>1∧containersOf(signatureBytes)>1∧uuidBytes<publicKeyBytes∧uuidBytes<signatureBytes∧uuidBytes⋅8<signatureBytes⋅8
widths.all (fun n => (containersOf n ≤ 1) == (n ≤ uuidBytes)) ∧ containersOf publicKeyBytes > 1 ∧ containersOf signatureBytes > 1 ∧ uuidBytes < publicKeyBytes ∧ uuidBytes < signatureBytes ∧ uuidBytes * 8 < signatureBytes * 8
LaTeX source
\forall n \in \mathrm{widths},\; \mathrm{containersOf}\mathopen{}\left(n\right) \le 1 = n \le \mathrm{uuidBytes} \land \mathrm{containersOf}\mathopen{}\left(\mathrm{publicKeyBytes}\right) > 1 \land \mathrm{containersOf}\mathopen{}\left(\mathrm{signatureBytes}\right) > 1 \land \mathrm{uuidBytes} < \mathrm{publicKeyBytes} \land \mathrm{uuidBytes} < \mathrm{signatureBytes} \land \mathrm{uuidBytes} \cdot 8 < \mathrm{signatureBytes} \cdot 8

FITTING INSIDE THE IDENTIFIER IS EXACTLY NEEDING ONE CONTAINER OR NONE — the two independent readings of "fits" agree at every width, so neither can be the one that lets a key in. The key and the signature are then refused by the law rather than by an inequality typed about them.

Proof. by decide — by evaluation; no domain is walked. □

Theorem 36 (not_even_the_whole_uuid_would_hold_one)sealed.

∀a∈widths,∀b∈widths,bitsOf(a)<bitsOf(b)=a<b∧bitsOf(uuidBytes)=128∧bitsOf(signatureBytes)=512∧128<512
widths.all (fun a => widths.all (fun b => (bitsOf a < bitsOf b) == (a < b))) ∧ bitsOf uuidBytes = 128 ∧ bitsOf signatureBytes = 512 ∧ 128 < 512
LaTeX source
\forall a \in \mathrm{widths},\; \forall b \in \mathrm{widths},\; \mathrm{bitsOf}\mathopen{}\left(a\right) < \mathrm{bitsOf}\mathopen{}\left(b\right) = a < b \land \mathrm{bitsOf}\mathopen{}\left(\mathrm{uuidBytes}\right) = 128 \land \mathrm{bitsOf}\mathopen{}\left(\mathrm{signatureBytes}\right) = 512 \land 128 < 512

and not even if the whole identifier were given over to it, reserved bits and all. THE UNITS CANNOT WIN THE ARGUMENT: multiplying by eight preserves strict order at every pair of widths, so restating a byte comparison in bits returns the same verdict and "but count the bits" is not an escape.

Proof. by decide — by evaluation; no domain is walked. □

Theorem 37 (what_travels_beside_the_identifier)sealed.

∀a∈widths,∀b∈widths,¬amoduuidBytes=0∧bmoduuidBytes=0∨a+bmoduuidBytes=0∧containersOf(a+b)=containersOf(a)+containersOf(b)∧containersOf(publicKeyBytes+signatureBytes)=6∧publicKeyBytes+signatureBytes=96∧96=6⋅uuidBytes
widths.all (fun a => widths.all (fun b => !(a % uuidBytes == 0 && b % uuidBytes == 0) || (((a + b) % uuidBytes == 0) && (containersOf (a + b) == containersOf a + containersOf b)))) ∧ containersOf (publicKeyBytes + signatureBytes) = 6 ∧ publicKeyBytes + signatureBytes = 96 ∧ 96 = 6 * uuidBytes
LaTeX source
\forall a \in \mathrm{widths},\; \forall b \in \mathrm{widths},\; \lnot a \bmod \mathrm{uuidBytes} = 0 \land b \bmod \mathrm{uuidBytes} = 0 \lor a + b \bmod \mathrm{uuidBytes} = 0 \land \mathrm{containersOf}\mathopen{}\left(a + b\right) = \mathrm{containersOf}\mathopen{}\left(a\right) + \mathrm{containersOf}\mathopen{}\left(b\right) \land \mathrm{containersOf}\mathopen{}\left(\mathrm{publicKeyBytes} + \mathrm{signatureBytes}\right) = 6 \land \mathrm{publicKeyBytes} + \mathrm{signatureBytes} = 96 \land 96 = 6 \cdot \mathrm{uuidBytes}

the pair travels together, and together they are six times the thing they attest. WHOLE CONTAINERS ADD: where both parts are whole multiples of the container, the escort is whole too and its count is the sum of the counts — decided at every such pair, so the six is the law's answer and not a sum somebody checked.

Proof. by decide — by evaluation; no domain is walked. □

Theorem 38 (the_check_cannot_separate_the_payloads)sealed.

∀c∈{0,…,11},∀q∈{0,…,11},2c<2q=c<q∧2≤2q2c=c<q∧2checkBits<2payloadBits∧payloadBits=90∧checkBits=32
(List.range 12).all (fun c => (List.range 12).all (fun q => ((2 ^ c < 2 ^ q) == (c < q)) && ((2 ≤ 2 ^ q / 2 ^ c) == (c < q)))) ∧ 2 ^ checkBits < 2 ^ payloadBits ∧ payloadBits = 90 ∧ checkBits = 32
LaTeX source
\forall c \in \{0,\dots,11\},\; \forall q \in \{0,\dots,11\},\; 2^{c} < 2^{q} = c < q \land 2 \le \frac{2^{q}}{2^{c}} = c < q \land 2^{\mathrm{checkBits}} < 2^{\mathrm{payloadBits}} \land \mathrm{payloadBits} = 90 \land \mathrm{checkBits} = 32

── A CHECKSUM CANNOT AUTHENTICATE, AND THIS IS COUNTING, NOT CRYPTOGRAPHY ─────────────────────────────── 90 bits of payload cannot be separated by 32 bits of check, so distinct payloads share a check by the pigeonhole alone — before any question of how good the function is. THE PIGEONHOLE IS THE LAW AND 32 < 90 IS ONE READING OF IT: at every pair of widths, the check separates the payloads exactly when it is at least as wide, and the number of payloads sharing a check value reaches two exactly when it is narrower. Both directions, so the statement cannot be satisfied by the easy half.

Proof. by decide — exhausting 144 cases. □

Theorem 39 (the_gap_is_fifty_eight_bits)sealed.

∀c∈{0,…,11},∀q∈{0,…,11},¬c≤q∨2q=2q-c⋅2c∧payloadBits-checkBits=58∧2payloadBits=258⋅2checkBits
(List.range 12).all (fun c => (List.range 12).all (fun q => !(c ≤ q) || (2 ^ q == 2 ^ (q - c) * 2 ^ c))) ∧ payloadBits - checkBits = 58 ∧ 2 ^ payloadBits = 2 ^ 58 * 2 ^ checkBits
LaTeX source
\forall c \in \{0,\dots,11\},\; \forall q \in \{0,\dots,11\},\; \lnot c \le q \lor 2^{q} = 2^{q - c} \cdot 2^{c} \land \mathrm{payloadBits} - \mathrm{checkBits} = 58 \land 2^{\mathrm{payloadBits}} = 2^{58} \cdot 2^{\mathrm{checkBits}}

the gap is not marginal: there are 2^58 payloads per check value on average. AND THE GAP IS A FACTOR, NOT A DIFFERENCE — the payload space is the check space multiplied by two to the gap, at every pair of widths where the check is no wider. Fifty-eight bits is that factor's exponent here, which is why subtracting the widths is the right arithmetic and subtracting the spaces would not be.

Proof. by decide — exhausting 144 cases. □

∀s∈{0,…,5},∀t∈{0,…,5},∀p∈{0,…,11},checkOf(s,p)=checkOf(t,p)
(List.range 6).all (fun s => (List.range 6).all (fun t => (List.range 12).all (fun p => checkOf s p == checkOf t p)))
LaTeX source
\forall s \in \{0,\dots,5\},\; \forall t \in \{0,\dots,5\},\; \forall p \in \{0,\dots,11\},\; \mathrm{checkOf}\mathopen{}\left(s,\,p\right) = \mathrm{checkOf}\mathopen{}\left(t,\,p\right)

A CHECKSUM IGNORES THE SECRET: every party computes the same value for the same payload, so it names nobody. Over every pair of secrets and every payload in range.

Theorem 41 (two_secrets_part_company_on_every_payload)sealed.

∀p∈{0,…,11},tagOf(1,p)≠tagOf(2,p)∧¬∀s∈{0,…,5},∀t∈{0,…,5},∀p∈{0,…,11},tagOf(s,p)=tagOf(t,p)
(List.range 12).all (fun p => tagOf 1 p != tagOf 2 p) ∧ ¬ ((List.range 6).all (fun s => (List.range 6).all (fun t => (List.range 12).all (fun p => tagOf s p == tagOf t p))))
LaTeX source
\forall p \in \{0,\dots,11\},\; \mathrm{tagOf}\mathopen{}\left(1,\,p\right) \neq \mathrm{tagOf}\mathopen{}\left(2,\,p\right) \land \lnot \forall s \in \{0,\dots,5\},\; \forall t \in \{0,\dots,5\},\; \forall p \in \{0,\dots,11\},\; \mathrm{tagOf}\mathopen{}\left(s,\,p\right) = \mathrm{tagOf}\mathopen{}\left(t,\,p\right)

A TAG DOES NOT: distinct secrets give distinct tags on every payload, which is what lets a verifier tell two parties apart. The identical quantification, and it comes out the other way.

Proof. by decide — exhausting 5,184 cases. □

and the tag really does depend on the payload too, or it would name the party and attest nothing

Theorem 43 (the_square_root_rule_is_the_one_this_prime_admits)sealed.

∀n∈{0,…,63},n+3mod8=0=nmod8=5∧¬nmod8=5∨nmod4=1∧nmod4≠3∧pmod8=5∧p+3mod8=0∧pmod4=1∧pmod4≠3
(List.range 64).all (fun n => (((n + 3) % 8 == 0) == (n % 8 == 5)) && (!(n % 8 == 5) || ((n % 4 == 1) && (n % 4 != 3)))) ∧ p % 8 = 5 ∧ (p + 3) % 8 = 0 ∧ p % 4 = 1 ∧ p % 4 ≠ 3
LaTeX source
\forall n \in \{0,\dots,63\},\; n + 3 \bmod 8 = 0 = n \bmod 8 = 5 \land \lnot n \bmod 8 = 5 \lor n \bmod 4 = 1 \land n \bmod 4 \neq 3 \land p \bmod 8 = 5 \land p + 3 \bmod 8 = 0 \land p \bmod 4 = 1 \land p \bmod 4 \neq 3

WHICH RULE A FIELD ADMITS IS A LAW ABOUT THE RESIDUE, NOT A FACT ABOUT THIS PRIME. The exponent (n+3)/8 the implementation raises to is a whole number at EXACTLY the residue 5 mod 8 — both directions, decided at every residue — and that residue forces n ≡ 1 mod 4, which is precisely what rules the (p+1)/4 branch out. So the fallback is not an extra precaution: it is the only rule this residue class has. 2^255 − 19 is then one argument to that law, and a port to another field is refused by the law rather than by a note.

Proof. by decide — exhausting 64 cases. □

Theorem 44 (the_cofactor_is_bracketed_at_eight)sealed.

∀h∈{0,…,16},h⋅L≤p∧p<h+1⋅L=h=7∧pL=7∧7⋅L≤p∧p<8⋅L∧4⋅L<p∧L<p
(List.range 17).all (fun h => ((h * L ≤ p) && (p < (h + 1) * L)) == (h == 7)) ∧ p / L = 7 ∧ 7 * L ≤ p ∧ p < 8 * L ∧ 4 * L < p ∧ L < p
LaTeX source
\forall h \in \{0,\dots,16\},\; h \cdot L \le p \land p < h + 1 \cdot L = h = 7 \land \frac{p}{L} = 7 \land 7 \cdot L \le p \land p < 8 \cdot L \land 4 \cdot L < p \land L < p

and the base point's order is the prime part of a group whose cofactor is eight. THE BRACKET WAS TOO LOOSE: 4L < p < 8L admits the eight but does not pin it, because it says nothing about 5L, 6L or 7L. The law is that EXACTLY ONE multiple of the order sits at or below p with the next above it, and that one is the seventh — decided against every candidate to sixteen, so eight is the LEAST cofactor whose multiple clears p and is pinned from below as well as above. That is the statement the typed bracket was standing in for.

Proof. by decide — exhausting 17 cases. □
