merkle.lean ​

src/iso/iec-9834-8-identifiers/merkle.lean · namespace Merkle · 16 theorems · wing the address

The fold, ported to Lean — merge, merkleFold, and the order-independence the deposit calls its receipt.

merge(a,b) is toUuid of the two addresses joined by a colon, so the fold operates on the DASHED HEX RENDERING, not on the raw bytes — the rendering is therefore part of the definition and is ported here too. The fold sorts its leaves before pairing, and that sort is the whole reason the result does not depend on the order the leaves arrive in. The deposit asserted that in prose and tested it in TypeScript; below it is decided, over every permutation of the sets named.

No axioms, no Mathlib, no sorry. Address and Fnv are imported, not restated.

Theorem 94 (singleton_fold_is_the_hashed_leaf)sealed.

merkleFold([A])=merkleLeaf(A)
merkleFold [A] = merkleLeaf A
LaTeX source
\mathrm{merkleFold}\mathopen{}\left([A]\right) = \mathrm{merkleLeaf}\mathopen{}\left(A\right)

── THE FOLD OF ONE LEAF IS NOT THAT LEAF, AND THAT IS THE FIX ───────────────────────────────────────────── This file used to decide `merkleFold [A] = A` and call it "the base case of the contraction". It was the second preimage: for any root R the one-leaf set [R] reproduced R, so two different leaf multisets shared an address and the result was not a commitment. The leaf is hashed under its own domain now, so a root is always a node value and no leaf can be mistaken for one.

Proof. by decide — by evaluation; no domain is walked. □

∀x∈[A,B,C],merkleFold([x])≠x

LaTeX source

Proof. by decide — by evaluation; no domain is walked. □

Theorem 96 (a_root_presented_as_a_leaf_is_a_different_root)sealed.

merkleFold([merkleFold([A,B])])≠merkleFold([A,B])
merkleFold [merkleFold [A, B]] != merkleFold [A, B]
LaTeX source
\mathrm{merkleFold}\mathopen{}\left([\mathrm{merkleFold}\mathopen{}\left([A,\,B]\right)]\right) \neq \mathrm{merkleFold}\mathopen{}\left([A,\,B]\right)

── AND THE FORGERY THE OLD SHAPE ALLOWED IS REFUSED ─────────────────────────────────────────────────────── Hand any root back as a lone leaf: it no longer reproduces itself.

Proof. by decide — by evaluation; no domain is walked. □

Theorem 97 (a_leaf_address_is_never_a_node_address)sealed.

∀x∈[A,B,C],merkleLeaf(x)≠merkleNode(A,B)
[A, B, C].all (fun x => merkleLeaf x != merkleNode A B)
LaTeX source
\forall x \in [A,\,B,\,C],\; \mathrm{merkleLeaf}\mathopen{}\left(x\right) \neq \mathrm{merkleNode}\mathopen{}\left(A,\,B\right)

── AND LEAF AND NODE DOMAINS NEVER MEET ─────────────────────────────────────────────────────────────────── Each address here is a full SHA computation in the kernel, so the 27 combinations of a triple loop ran past the heartbeat limit. Three leaves against one node is the same claim at the scale this can decide, and the general separation is structural: the two domains differ in their first twelve bytes.

Proof. by decide — by evaluation; no domain is walked. □

Theorem 100 (merge_is_order_sensitive)sealed.

merge(A,B)≠merge(B,A)

LaTeX source
\mathrm{merge}\mathopen{}\left(A,\,B\right) \neq \mathrm{merge}\mathopen{}\left(B,\,A\right)

── and it is not vacuous: merge itself IS order-sensitive; the sort is what removes the dependence ──

Proof. by decide — by evaluation; no domain is walked. □

Theorem 101 (merge_is_injective_on_these_pairs)sealed.

merge(A,B)≠merge(A,C)∧merge(A,B)≠merge(B,B)∧merge(B,C)≠merge(C,B)
merge A B != merge A C && merge A B != merge B B && merge B C != merge C B
LaTeX source
\mathrm{merge}\mathopen{}\left(A,\,B\right) \neq \mathrm{merge}\mathopen{}\left(A,\,C\right) \land \mathrm{merge}\mathopen{}\left(A,\,B\right) \neq \mathrm{merge}\mathopen{}\left(B,\,B\right) \land \mathrm{merge}\mathopen{}\left(B,\,C\right) \neq \mathrm{merge}\mathopen{}\left(C,\,B\right)

── THE SEPARATOR IS ESCAPED NOW, SO THE PAIR IS RECOVERABLE ─────────────────────────────────────────────── merge("a:b","c") and merge("a","b:c") were one address. Each part carries its own length, so no concatenation of one pair spells another — decided here on the addresses this file works with.

Proof. by decide — by evaluation; no domain is walked. □

Theorem 103 (the_permutation_generator_is_complete)sealed.
