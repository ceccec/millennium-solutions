qc_status.lean ​

src/iso/iec-4879-quantum/qc_status.lean · namespace QcStatus · 40 theorems · wing unassigned

The qpu get_qc tool returns a status, not a bare boolean: a list of gaps, each OPEN or CLOSED with the condition that closes it (src ~/github/uuidna/qpu/src/quantum/uuid/programs/get_qc/index.ts). This file seals the HONEST LOGIC of that status — it decides list facts about the gap taxonomy, and claims nothing about the physical world. Two kinds of gap: · SOFTWARE/PROOF gaps — closeable by code: the exhaustive gap-map (each apparatus conjunct its own lead), the classical-device-id refusal, the 4879 "measured-not-proved" boundary, the receipt≠physical-QM boundary, the content-address seals, the indexed install, the 122 register, the NIST/CERN+PQC seals. · WORLD gaps — NOT closeable by any computation: (1) accredited physical-lab apparatus evidence (ISO 17025 × 17065 × universality — a real device measured in an accredited lab), and (2) the FULL factorisation of 2^999+1 (an open problem; the deposit has it only as PARTIAL). The point sealed here: closing EVERY software gap does NOT make the verdict true — the two world-gaps dominate it — so no amount of code can fabricate isQuantumComputer: true. The status is OPEN (incomplete), which is neither a refusal (not every gap is unclosable) nor a claim (the world-gaps are open). The two world-gaps are modelled OPEN because they are open; if one day either is met, this list changes and the verdict follows. Honest floor: isQuantumComputer is false BECAUSE a world-gap is open, by this logic.
