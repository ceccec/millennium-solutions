qpu_fold.lean ​

src/iso/iec-4879-quantum/qpu_fold.lean · namespace QpuFold · 8 theorems · wing the ring

WHY THIS FILE EXISTS.

src/iso/22739-ledger/capacity.lean decides that a UUID leaves 122 free bits, and qpu's README reads that as 2^122 values and a Grover cost of 2^61 = √(2^122). But qpu's coins are not drawn from the 122-bit layout. They are content addresses: uuid(text) folds the text to a 64-bit FNV-1a state and lays every output digit out from that state (the high half is the state; the low half is foldFrom(state, '\u0000shape'), a function of the state; the version nibble is decided by the other 31). So the whole 122-bit address is a function of a 64-bit value, and a function of a 64-bit value takes at most 2^64 outputs however wide its codomain is. The 122-bit layout is the codomain; the 64-bit fold is the domain; 2^122 − 2^64 of the layout's addresses are never the content address of anything.

WHAT THIS MEANS FOR A SEARCH, which the question raised. A coin may of course be searched, and a search MEASURES a floor rather than proving a strength: it is the width that sets the floor, and the width here is 64, not 122. Classical preimage of a content coin costs at most 2^64, its Grover preimage about 2^32 = √2^64, and a birthday collision about 2^32 — each below the 2^61 the README quotes against the full layout. This file decides that gap. It does not call the coin broken: 2^32 is real work, and the coin is an identifier, not a key (RFC 9562 §8). It states where the floor is, measured from qpu's own fold.

THE BOUND IS MODELLED AT SMALL WIDTH, by the deposit's rule: 2^64 cannot be enumerated, so the mechanism — a narrow intermediate caps the image, and widening it lifts the cap — is decided at four bits against eight, and the real 64-against-122 is carried as arithmetic. No step claims to enumerate 2^64.

No axioms, no Mathlib, no sorry.

Theorem 992 (the_real_fold_is_sixty_four_bits_against_the_hundred_twenty_two_bit_layout)sealed.

∀w∈{0,…,122},2w⋅2122-w=2122∧decide(w<122)=decide(2w<2122)∧264⋅258=2122∧2122-264>0∧mask⋅mask⋅mask⋅mask=264

LaTeX source

── 7 · THE REAL FOLD IS SIXTY-FOUR BITS AGAINST A HUNDRED-TWENTY-TWO-BIT LAYOUT ────────────────────────── The numbers the model stands in for: 2^64 coins at most, 2^122 addresses, a gap of 58 bits, and 2^122 − 2^64 addresses that no content reaches. 2^64 · 2^58 = 2^122 states the gap as a factor, not an impression. AS A LAW, NOT A READ-BACK: for EVERY fold width w a 122-bit layout can hold, the gap factor is 2^(122−w), and the inverse holds at every instance — a fold narrower than the layout leaves addresses unreached exactly when w < 122, and only the full width w = 122 leaves none. qpu's 64 is one instance of the 123 decided.

Proof. by decide — exhausting 123 cases. □

Theorem 993 (the_search_floor_is_the_fold_width_not_the_layout_width)sealed.

LaTeX source

── 8 · THE SEARCH FLOOR IS THE FOLD WIDTH, NOT THE LAYOUT WIDTH ────────────────────────────────────────── A Grover preimage or a birthday collision costs about the square root of the search space. qpu's README takes the space to be 2^122 and reads 2^61. The content space is 2^64, so the measured floor is 2^32 = √2^64: below the README's 2^61, and far below the 2^122 layout. The exponents are each half their width.

Proof. by decide — by evaluation; no domain is walked. □
